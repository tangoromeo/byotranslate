# bench — замер качества перевода моделей

Инструмент для B5/B1: сравнить модели OpenRouter на реальных человеческих
переводах и увидеть, где разница настоящая, а где шум. Не зависит от
приложения, кроме одного: системный промпт берётся из
`LLMTranslateKit/Sources/Prompting/PromptBuilder.swift`, поэтому замер отражает
то, что делает приложение.

## Что это измеряет — и чего не измеряет

- **chrF++** — совпадение с профессиональным переводом по символьным и
  словным n-граммам. Хороший перевод другими словами получит меньше, поэтому
  цифра — «насколько близко к эталону», а не «насколько хорошо».
- **Доверительный интервал** (bootstrap, 95%) у каждой модели и **парное
  сравнение с лидером**. Отличие внутри шума помечено `≈ лучшая (в шуме)`.
- Задержка (медиана), число сбоев, стоимость на 1000 предложений.
- Не измеряет: перевод строк интерфейса, терминологию банка, стиль. Для этого
  нужны ваши собственные строки (слепое сравнение, отдельный шаг).
- Корпуса публичные, модели могли их видеть при обучении — абсолютные числа
  завышены, сравнение моделей между собой остаётся осмысленным.

## Запуск

```bash
export OPENROUTER_API_KEY=...        # только в окружении, нигде не сохраняется
python3 bench.py list-models --grep gemini
cp models.example.txt models.txt     # отредактировать
python3 bench.py run --models models.txt --pair he-ru --corpus ntrex --n 100
python3 bench.py report --results results/<файл>.jsonl
python3 -m unittest -q               # тесты метрики и загрузчиков
```

Расход ≈ `n × число моделей` запросов; цена на 1000 предложений печатается в
таблице. Сначала `--n 30` на одной-двух моделях, чтобы оценить стоимость.
