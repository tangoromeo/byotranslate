# ТЗ: iOS-приложение «стандартный переводчик» на базе LLM с пользовательским API-ключом

**Кодовое имя:** `LLMTranslate` (заменить на финальное)
**Адресат документа:** кодинг-агент (Claude Code)
**Версия ТЗ:** 1.3
**Дата:** 2026-09-11
**Сопутствующие документы:** `docs/BACKLOG.md` — отложенное за пределы v1

---

## 0. Цель и критерий успеха

Пользователь выделяет текст в **любом** приложении iOS, жмёт **«Перевести»** в стандартном контекстном меню — и получает перевод, сделанный LLM по его собственному API-ключу и его собственному промпту, а не Google/Apple Translate. Отдельным сценарием — перевод скриншота одним жестом.

**Критерий успеха v1:** после установки и ввода ключа пункт «Перевести» в системном меню выделения работает через выбранную пользователем модель. Пользователь не совершает ни одного дополнительного тапа по сравнению со штатным переводчиком.

**Продуктовый тезис:** штатные переводчики плохи на редких парах (иврит→русский), на технических текстах и на тексте с терминологией. LLM с настраиваемым промптом и глоссарием решает именно это. Всё, что не служит этому тезису, — вне v1.

**Главная валюта проекта — латентность, а не деньги.** Типичное выделение стоит доли цента даже на дорогой модели; сэкономить на этом нечего. А вот приложение, думающее три секунды там, где штатный переводчик отвечает мгновенно, будет заброшено независимо от качества перевода. Все компромиссы решаются в пользу скорости отклика. Единственное место, где стоимость реально значима, — изображения (раздел 10.7).

## 2. Платформа и жёсткие ограничения

- **Минимальная версия:** iOS 18.4 / iPadOS 18.4. Ниже механизм стандартного переводчика не существует.
- **Язык:** Swift 6, SwiftUI. Строгий concurrency-режим.
- **Зависимости:** только системные фреймворки. Никаких сторонних пакетов (Alamofire, SwiftyJSON и т. п.). Сетевой слой — `URLSession`.
- **Целевая сборка:** Xcode, стандартный проект, без CocoaPods/SPM-зависимостей.

## 3. Архитектура: таргеты

```
LLMTranslate.xcodeproj
├── LLMTranslate                  (app)                  — настройки, онбординг, экран результата
├── LLMTranslateTextExt           (TranslationUIProvider) — шторка перевода выделенного текста
├── LLMTranslateShareExt          (Share Extension)       — приём изображений
├── LLMTranslateControl           (Widget ext. / Control)  — кнопка Пункта управления
└── LLMTranslateKit               (shared framework)      — провайдеры, Keychain, промптинг, кэш, счётчик
```

`LLMTranslateKit` линкуется во все таргеты. Вся логика перевода — там. Расширения содержат только UI и связывание с системным контекстом.

App Intents (`AppShortcutsProvider`) объявляются в **основном таргете приложения** — расширению они не нужны.

**Расширения работают в отдельных процессах.** Из этого следует всё, что написано в разделах 5 и 14 — не игнорировать.

## 4. Ключевой API-контракт перевода текста (проверено по документации Apple)

### 4.1 Entitlement приложения

```
com.apple.developer.translation-app  →  Boolean  →  true
```

Добавляется в Xcode: target приложения → Signing & Capabilities → «+ Capability» → «Translation».
**Заявки в Apple на этот entitlement не требуется** — по документации это обычная capability.

### 4.2 Ключ Info.plist приложения

```
com.apple.developer.translation-ui-provider.network-access  →  Boolean  →  true
```

Без него расширение не получит доступ к сети. Обязателен, так как перевод идёт через облачный API.

### 4.3 Точка входа расширения

Фреймворк `TranslationUIProvider`, доступен с iOS 18.4 / iPadOS 18.4 / Mac Catalyst 18.4.

```swift
import SwiftUI
import TranslationUIProvider

@main
class TranslateExtension: TranslationUIProviderExtension {
    var body: some TranslationUIProviderExtensionScene {
        TranslationUIProviderSelectedTextScene { context in
            TranslateSheetView(context: context)
        }
    }
}
```

### 4.4 `TranslationUIProviderContext` — весь доступный контракт

Протокол, наследует `Observable`. Даёт **только** это:

| Член | Тип | Назначение |
|------|-----|------------|
| `inputText` | `AttributedString?` | Исходный текст. Может быть `nil` или пустым — обрабатывать. |
| `allowsReplacement` | `Bool` | Можно ли заменить исходный текст. `false`, когда поле нередактируемое. |
| `finish(translation:)` | метод | Завершить и закрыть шторку, вернув перевод в исходное поле. |
| `expandSheet()` | метод | Попросить систему развернуть шторку. |

**Критично для проектирования:** система **не передаёт** ни исходный, ни целевой язык, ни идентификатор приложения-источника, ни какой-либо иной контекст. Только текст. Определение языка и выбор целевого — целиком на нашей стороне (раздел 7).

### 4.5 ⚠️ Известное расхождение в документации Apple

Справочник фреймворка называет метод завершения `finish(translation:)`.
Пример кода в статье «Preparing your app to be the default translation app» использует `context.finish(replacingWithTranslation: AttributedString(...))`.

**Действие агента:** не доверять ни тому, ни другому. Взять фактическую сигнатуру из SDK (⌘-клик по типу в Xcode или `swift-api-digester`), зафиксировать реальное имя в комментарии в коде и в `NOTES.md`. Это первое, что нужно проверить при старте, до написания UI.

## 5. Хранение секретов

API-ключи хранятся **только** в Keychain, с общей группой доступа между приложением и всеми расширениями.

```
Keychain Access Group: $(AppIdentifierPrefix)com.<company>.llmtranslate.shared
kSecClass:            kSecClassGenericPassword
kSecAttrService:      "com.<company>.llmtranslate.apikey.<slotID>"
kSecAttrAccessible:   kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly
```

`slotID` — идентификатор слота модели (`working` / `strong`, см. раздел 11.2), а не провайдера: у слотов могут быть разные провайдеры и разные ключи.

Требования:

- `kSecAttrSynchronizable = false`. Ключи не уезжают в iCloud Keychain.
- Все таргеты объявляют Keychain Sharing с одной и той же группой.
- Ключ **никогда** не логируется, не попадает в `os_log`, не пишется в `UserDefaults`, не отображается в UI в открытом виде после сохранения (показывать маску `sk-…3f9a`).
- Ключ шифрования кэша (раздел 11.4) хранится там же, отдельной записью.
- Несекретные настройки (провайдеры, модели, целевые языки, промпты, глоссарий, счётчик) — в общем `UserDefaults(suiteName:)` через App Group `group.com.<company>.llmtranslate`.

## 6. Провайдеры LLM

### 6.1 Абстракция

```swift
public protocol TranslationProvider: Sendable {
    var id: ProviderID { get }
    /// Потоковая выдача. Возвращает дельты сырого текста ответа модели.
    func stream(request: TranslationRequest) -> AsyncThrowingStream<StreamEvent, Error>
    /// Проверка ключа и доступности модели. Для кнопки «Проверить» в настройках.
    func validate() async throws -> ProviderCapabilities
    /// Список моделей, если API его отдаёт.
    func listModels() async throws -> [ModelDescriptor]
}

public enum StreamEvent: Sendable {
    case delta(String)
    case usage(promptTokens: Int?, completionTokens: Int?)   // если провайдер отдаёт
}

public struct TranslationRequest: Sendable {
    let payload: Payload                           // .text(String) | .image(Data, mime: String)
    let detectedSourceLanguage: Locale.Language?   // nil == не определён
    let targetLanguage: Locale.Language
    let mode: TranslationMode                      // .plain | .withNotes | .dictionary
    let systemPrompt: String
    let glossary: [String: String]
    let maxOutputTokens: Int
}
```

Текст и изображение проходят через **один и тот же** протокол и один и тот же стриминговый конвейер. Не заводить параллельную ветку кода для картинок.

### 6.2 Три адаптера — текст

| Провайдер | Endpoint (настраиваемый) | Аутентификация | Формат стрима |
|-----------|--------------------------|----------------|---------------|
| OpenAI-совместимый | `{baseURL}/chat/completions`, по умолчанию `https://api.openai.com/v1` | `Authorization: Bearer <key>` | SSE, `data: {...}`, дельта в `choices[0].delta.content`, терминатор `data: [DONE]` |
| Anthropic | `{baseURL}/messages`, по умолчанию `https://api.anthropic.com/v1` | `x-api-key: <key>` + `anthropic-version: <значение из настроек>` | SSE, события `content_block_delta`, текст в `delta.text` |
| Google Gemini | `{baseURL}/models/{model}:streamGenerateContent`, по умолчанию `https://generativelanguage.googleapis.com/v1beta` | `x-goog-api-key: <key>` | потоковый JSON, текст в `candidates[0].content.parts[0].text` |

### 6.3 Три адаптера — изображение

| Провайдер | Форма сообщения |
|-----------|-----------------|
| OpenAI-совместимый | `content: [{"type":"text","text":"…"},{"type":"image_url","image_url":{"url":"data:image/jpeg;base64,…"}}]` |
| Anthropic | `content: [{"type":"image","source":{"type":"base64","media_type":"image/jpeg","data":"…"}},{"type":"text","text":"…"}]` |
| Google Gemini | `parts: [{"inline_data":{"mime_type":"image/jpeg","data":"…"}},{"text":"…"}]` |

В настройках слота — флаг «модель поддерживает изображения». Не все модели мультимодальны; при выключенном флаге пункты перевода скриншота дизейблить с пояснением, а не падать в ошибку API.

### 6.4 Общие требования к адаптерам

1. `baseURL` **настраиваемый для всех трёх**. Это даёт поддержку OpenRouter, Groq, DeepSeek, Azure OpenAI, корпоративных прокси и локального Ollama/LM Studio без единой строки нового кода.
2. **Не хардкодить идентификаторы моделей.** Модель — строка из настроек. Список для выпадающего меню тянуть через `listModels()`. Если запрос списка не удался — оставить свободный ввод строки. Никаких зашитых `gpt-…`/`claude-…` в коде: они устаревают быстрее релизного цикла.
3. Стриминг обязателен для всех трёх, для обоих типов ввода и для всех режимов.
4. Извлекать `usage` из ответа там, где провайдер его отдаёт, и прокидывать событием `.usage` для F15. Где не отдаёт — **не оценивать самостоятельно**, счётчик покажет прочерк.
5. Таймауты: 8 с до первого байта для текста, 20 с для изображения; 30 с и 60 с на весь ответ соответственно. Все настраиваемые в отладочной секции.
6. Ретрай: один повтор на сетевую ошибку и на HTTP 429/5xx, экспоненциальная задержка от 500 мс. На 401/403 — не повторять, сразу в ошибку аутентификации.
7. Форматы запросов в 6.2 и 6.3 приведены как ориентир и **подлежат сверке с актуальной документацией провайдера на момент реализации**.

## 7. Определение языковой пары

Система языков не передаёт. Алгоритм:

1. Определить язык источника локально: `NLLanguageRecognizer` из `NaturalLanguage`, по первым 500 символам. Забрать топ-2 гипотезы с вероятностями.
2. Взять `primaryTarget` из настроек (по умолчанию — язык интерфейса устройства).
3. Если определённый язык **не равен** `primaryTarget` → переводим в `primaryTarget`.
4. Если определённый язык **равен** `primaryTarget` → переводим в `secondaryTarget` из настроек.
5. Если уверенность распознавания ниже 0.5 или текст короче 3 символов → язык источника не передаём (`detectedSourceLanguage = nil`), в промпте пишем «определи язык сам».
6. Определённый язык показывать в шапке шторки чипом, с возможностью тапнуть и переопределить пару вручную для текущего перевода. Ручной выбор не сохраняется в настройки.

Для изображений локальное определение языка не выполняется — язык определяет модель.

## 8. Промптинг

### 8.1 Режимы

```swift
enum TranslationMode { case plain, withNotes, dictionary }
```

- `.plain` — только перевод. Режим по умолчанию для любого входа.
- `.withNotes` — перевод плюс комментарии. Включается кнопкой «Пояснить» или настройкой.
- `.dictionary` — словарный режим для коротких выделений (раздел 11.3).

### 8.2 Системный промпт для текста, режим `.plain`

Редактируемый пользователем, с кнопкой «сбросить к исходному». Базовая версия:

```
Ты — переводчик. Переведи текст пользователя на {targetLanguage}.

Правила:
- Выводи ТОЛЬКО перевод. Никаких пояснений, преамбул, извинений, кавычек вокруг результата.
- Сохраняй регистр, пунктуацию, переносы строк и разметку исходника.
- Сохраняй без перевода: имена собственные, названия компаний и продуктов,
  идентификаторы, код, URL, email, числа, единицы измерения.
- Если текст — фрагмент без контекста, переводи его как фрагмент,
  не достраивай предложение.
{glossarySection}
```

`{glossarySection}` подставляется только при непустом глоссарии:

```
- Обязательная терминология (используй строго эти соответствия):
  {term} → {translation}
```

### 8.3 Надстройка для режима `.withNotes`

К промпту `.plain` **добавляется** блок (не заменяет его):

```
После перевода выведи отдельной строкой маркер ⟦NOTES⟧, а под ним — краткие пояснения.

В пояснениях допустимо ТОЛЬКО следующее:
- альтернативные варианты перевода неоднозначных мест, не более трёх;
- расшифровка идиом, реалий, игры слов;
- пометка, если тон или регистр исходника передать не удалось;
- транслитерация имён собственных.

Запрещено: пересказывать текст, оценивать его, рассуждать о языке вообще,
объяснять очевидное, извиняться.

Каждое пояснение — одна строка, начинается с «— ».
Если пояснять нечего, не выводи ни маркер, ни блок.
```

### 8.4 Надстройка для режима `.dictionary`

Заменяет тело промпта `.plain`:

```
Пользователь выделил короткий фрагмент — слово или короткую фразу.
Дай перевод на {targetLanguage} как словарная статья.

Первой строкой — самый частотный перевод, без пояснений.
Затем маркер ⟦NOTES⟧, под ним:
- до трёх альтернативных значений с пометкой контекста в скобках;
- часть речи и, для {targetLanguage} == русский, род существительных;
- транслитерация исходного слова русскими буквами, если исходный язык
  использует нелатинскую письменность.

Каждый пункт — одна строка, начинается с «— ». Без примеров употребления,
без этимологии, без рассуждений.
{glossarySection}
```

### 8.5 Системный промпт для изображения

Отдельный, тоже редактируемый:

```
На изображении — снимок экрана или фотография текста.
Извлеки весь текст и переведи его на {targetLanguage}.

Правила:
- Выводи ТОЛЬКО перевод, без описания изображения и без комментариев.
- Сохраняй структуру: абзацы, списки, таблицы, порядок блоков сверху вниз.
- Интерфейсные элементы (кнопки, пункты меню, поля) выводи отдельными строками
  в том порядке, в котором они расположены.
- Не переводи: имена собственные, названия компаний и продуктов, URL, email,
  номера счетов, идентификаторы, числа.
- Нечитаемый фрагмент помечай как [неразборчиво], не додумывай.
{glossarySection}
```

Надстройка `.withNotes` применима и к изображениям.

### 8.6 Пользовательское сообщение

Для текста — только исходный текст, без обёрток и без «переведи это:». Обёртки провоцируют модель на комментарии. Для изображения — само изображение плюс пустая или минимальная текстовая часть.

### 8.7 Разбор потока и маркер

**Маркер — ровно `⟦NOTES⟧`.** Не использовать `---` или другие ходовые последовательности: они встречаются в обычном тексте и в markdown, что даёт ложные срабатывания.

Требования к разбору:

1. Разбор **потоковый**, не по завершении ответа: всё, что пришло до маркера, немедленно рендерится как перевод.
2. Маркер может прийти разорванным между чанками. Держать хвостовой буфер длиной не меньше маркера и не отдавать в UI последние N символов, пока не станет ясно, что это не начало маркера.
3. Всё после маркера — комментарии, копятся в отдельную коллекцию, разбиваются по строкам, ведущее «— » срезается.
4. **Маркер не пришёл — это норма, а не ошибка.** Весь вывод считается переводом, секция комментариев не отображается.
5. Маркер пришёл, но блок под ним пуст — секция не отображается.
6. Если маркер каким-то образом встретился в исходном тексте пользователя, это не наша забота: перевод такого текста и так вырожденный случай.

### 8.8 Постобработка

Санитизация применяется **только к части «перевод»**, никогда к комментариям:

- Снять обрамляющие кавычки, если их не было в исходнике.
- Снять ведущие префиксы вида `Перевод:`, `Translation:`, `Вот перевод:`, `На изображении:` (регистронезависимо, только в начале).
- Снять обрамляющие блоки ``` ``` , если их не было в исходнике.
- Обрезать ведущие/замыкающие пустые строки.

Санитизация — отдельная чистая функция с юнит-тестами (раздел 15).

### 8.9 Профили промптов (опционально, если укладывается в срок)

Именованные наборы {промпт + глоссарий + языковая пара}: «Технический», «Бытовой», «Юридический». Переключение — чипами в шапке шторки. Если не успевается — по одному активному промпту на тип ввода, профили в v2.

## 9. UI шторки перевода текста

Компактная шторка, разворачиваемая через `context.expandSheet()`.

| Состояние | Отображение |
|-----------|-------------|
| `translating` | Исходный текст приглушённо + перевод, дописывающийся потоком + индикатор. |
| `done` | Перевод. Кнопки: «Копировать», «Заменить» (при `allowsReplacement == true`), «Точнее» (раздел 11.2), «Пояснить» (раздел 11.3). Свёрнутая секция «Пояснения (N)», если они есть. |
| `error` | Понятное сообщение (раздел 12) + «Повторить» + «Открыть настройки». |
| `notConfigured` | «Ключ не задан» + кнопка, открывающая хост-приложение по URL-схеме. |

Требования:

- Перевод стартует **автоматически** при появлении шторки. Никакой кнопки «Перевести» — это лишний тап, который убивает весь смысл затеи.
- Кнопка «Заменить» вызывает метод завершения из п. 4.5 и закрывает шторку. Скрывать, а не дизейблить, когда `allowsReplacement == false`.
- Длинный текст: шторка скроллится, автоматически вызывать `expandSheet()`, если исходный текст длиннее 200 символов.
- Тап по переводу — копирование в буфер с хаптиком и короткой плашкой «Скопировано».
- Секция «Пояснения» **никогда не разворачивается автоматически**, даже когда комментарии пришли. Иначе шторка распухает и главное тонет.
- Поддержать Dynamic Type, тёмную тему, RTL-раскладку (иврит и арабский — целевые языки, текст должен выравниваться по правому краю при RTL-результате).
- `inputText == nil` или пустая строка → показать «Нечего переводить», не отправлять запрос.

## 10. Перевод скриншотов и точки входа автоматизации

### 10.1 Чего в iOS не существует — прочитать до проектирования

1. **Триггера автоматизации «сделан скриншот» в iOS нет.** Проверено по списку личных автоматизаций Apple: события, поездки, связь, транзакции и настройки (Wi-Fi, Bluetooth, Фокус, режим энергосбережения, уровень заряда, зарядка, NFC, приложение, авиарежим). Скриншота там нет. Сценарий «сделал скриншот — перевод появился сам» **нереализуем**. Минимум — один явный жест пользователя.
2. **Хука «Перевести» для изображений в системном меню нет.** `TranslationUIProvider` работает только с выделенным текстом.

Не тратить время на попытки обойти эти два пункта.

### 10.2 Три реализуемые точки входа

| # | Механизм | Жест пользователя | Таргет |
|---|----------|-------------------|--------|
| E1 | Share Extension | скриншот → тап по превью → «Поделиться» → наше приложение. Либо «Фото» → «Поделиться». | `LLMTranslateShareExt` |
| E2 | App Intent + App Shortcut «Перевести последний скриншот» | голосом; из «Команд»; назначением на Back Tap; назначением на кнопку «Действие». | app target |
| E3 | Control Center control | кнопка в Пункте управления; та же кнопка назначается на кнопку «Действие» (iPhone 15 Pro и новее). | `LLMTranslateControl` |

**E3 — самый быстрый путь для пользователя:** нажал кнопку «Действие» → перевод последнего скриншота. Ближайшее из возможного к «автоматически».

### 10.3 Требования к Share Extension (E1)

- `NSExtensionActivationRule`: `NSExtensionActivationSupportsImageWithMaxCount = 1`. Текст **не** принимать — для текста работает F1.
- Немедленно показывает свой UI и стартует перевод, без промежуточных экранов подтверждения.
- Тот же UI результата, что и в остальных точках входа — общий SwiftUI-компонент из `LLMTranslateKit`.

### 10.4 Требования к App Intent (E2)

- Интент `TranslateLatestScreenshotIntent`, `openAppWhenRun = true`.
- Берёт последний элемент из смарт-альбома «Снимки экрана» (`PHAssetCollectionSubtype.smartAlbumScreenshots`) через `PHPhotoLibrary`.
- Запрос доступа к «Фото» — только по факту первого вызова, с внятным `NSPhotoLibraryUsageDescription`. Не просить доступ на онбординге.
- Если скриншотов нет или доступ не выдан — понятная ошибка, а не тихий выход.
- Второй интент `TranslateImageIntent` с параметром-изображением: принимает картинку из любой пользовательской команды.

### 10.5 Требования к Control (E3)

- `ControlWidget` с `ControlWidgetButton`, запускающий `TranslateLatestScreenshotIntent`.
- Иконка и подпись должны читаться в Пункте управления в компактном размере.

### 10.6 Обработка изображения — решение и обоснование

**Основной путь: изображение отправляется прямо в мультимодальную модель.** OCR и перевод — один запрос.

Почему не «Vision OCR → текст → перевод текстом»:

- `RecognizeTextRequest` поддерживает ограниченный набор языков, состав которого различается между версиями ОС и ревизиями модели. Запрашивать его надо в рантайме через `supportedRecognitionLanguages()`. Поддержка иврита не гарантирована — **проверить фактический список на устройстве и записать в `NOTES.md`**.
- Мультимодальная модель сохраняет структуру (таблицы, интерфейс, подписи) и разбирает текст в контексте, чего конвейер «плоский OCR → перевод» не даёт.

**Опциональный быстрый путь (реализовать, если укладывается в срок):** если язык, определённый по изображению, входит в `supportedRecognitionLanguages()`, сделать OCR локально и отправить текстовый запрос — это дешевле по токенам в разы. Переключатель в настройках, по умолчанию выключен.

### 10.7 Подготовка изображения перед отправкой

Единственное место в проекте, где стоимость запроса значима: изображение — это сотни-тысячи входных токенов против десятков у текста.

- Даунскейл до 1568 px по длинной стороне для фотографий. Для скриншотов интерфейса — 1024 px: там крупный текст, и разница в качестве распознавания незаметна, а экономия входных токенов кратная. Различать по соотношению сторон и метаданным ассета (скриншот приходит из смарт-альбома «Снимки экрана»).
- JPEG, качество 0.8. PNG использовать только если исходник PNG и меньше 300 КБ.
- Base64, ограничение полезной нагрузки 4 МБ. Превышение — понижать качество ступенчато до 0.5, затем разрешение до 1024/768 px, затем ошибка.
- Изображение не сохраняется на диск ни в каком виде, в том числе во временную директорию. Изображения **никогда не кэшируются** (раздел 11.4).

### 10.8 UI результата перевода изображения

- Полноэкранный результат: перевод потоком, миниатюра исходника сверху, тап по ней — просмотр оригинала.
- Кнопки «Копировать», «Поделиться», «Точнее», «Пояснить», «Ещё раз».
- Кнопки «Заменить» нет — заменять нечего.

## 11. Качество, стоимость и скорость

### 11.1 Что сознательно НЕ делается

**Автоматический выбор модели по эвристикам не реализуется.** Ни по длине текста, ни по языку, ни по «сложности», ни по оценке уверенности вторым запросом.

Причины:

- Роутер по эвристикам ошибается в обе стороны, а пользователь не понимает, почему один перевод хороший, а другой нет. Непредсказуемое качество хуже стабильно среднего.
- Схема «дешёвая модель переводит, дешёвая же оценивает уверенность, при низкой эскалируем» стоит двух вызовов вместо одного и добавляет секунды латентности — то есть жертвует главной валютой проекта ради экономии долей цента.
- Решение «важен ли этот текст» принимается на основании контекста, которого у приложения нет, а у человека есть.

Вместо роутера — **эскалация по требованию** (11.2 и 11.3). Это один механизм второго запроса, обслуживающий два разных сценария; реализуется однократно.

### 11.2 Слоты моделей и кнопка «Точнее» (F12)

Настраиваются два независимых **слота**, каждый — полный набор {провайдер, baseURL, ключ, модель, флаг мультимодальности}:

- `working` — рабочий. Быстрый и дешёвый. Используется всегда по умолчанию.
- `strong` — сильный. Необязателен.

Слоты независимы: рабочей моделью может быть дешёвая через OpenRouter, сильной — Anthropic напрямую. Это прямое следствие требования 6.4.1.

Поведение:

- Любой перевод стартует на `working`. Автоматического переключения нет никогда.
- Под результатом — кнопка **«Точнее»**: повторяет запрос на `strong` с тем же промптом и тем же режимом. Результат заменяет предыдущий.
- После эскалации показывать, какой моделью сделан текущий результат — мелкой подписью. Иначе пользователь не понимает, что перед ним.
- Если `strong` не настроен, кнопка скрыта, а не задизейблена.
- Повторное нажатие «Точнее» на уже эскалированном результате ничего не делает — кнопка исчезает.

### 11.3 Комментарии модели и словарный режим (F13)

**Настройка `notesMode`, по умолчанию `.off`:**

| Значение | Поведение |
|----------|-----------|
| `.off` (умолчание) | Перевод без комментариев. Кнопка «Пояснить» доступна. |
| `.shortOnly` | Комментарии приходят сразу для коротких выделений, для длинных — по кнопке. |
| `.always` | Комментарии приходят всегда. |

Кнопка **«Пояснить»** доступна в любом режиме и делает второй запрос в режиме `.withNotes` по тому же исходному тексту. Она — основной способ получить пояснения; настройка нужна тем, кому это требуется постоянно.

**Словарный режим.** Короткое выделение и длинное — это два разных запроса пользователя, случайно попавшие в один пункт меню:

- выделили слово или фразу → нужен **словарь**: варианты, оттенки, чтение;
- выделили абзац → нужен **переводчик**: смысл, быстро, без шума.

Поэтому: если исходный текст содержит **не более 4 слов и не более 30 символов**, режим автоматически становится `.dictionary` (промпт 8.4), и его вывод показывается с раскрытой секцией вариантов — здесь варианты и есть то, за чем пришли. Пороги вынести в настройки, значения по умолчанию — указанные.

Словарный режим действует независимо от `notesMode` и не отключается им. Отключается отдельным переключателем «Словарь для коротких выделений», по умолчанию включённым.

### 11.4 Кэш переводов (F14)

**По умолчанию выключен.** Это осознанный размен приватности на скорость, и пользователь должен включить его сам, прочитав, на что соглашается.

Что даёт: не экономию денег, а нулевую латентность на повторе. Один и тот же текст перечитывают чаще, чем кажется.

Механика:

- Ключ: SHA-256 от конкатенации нормализованного исходного текста, кода языка источника, кода целевого языка, идентификатора слота, имени модели, хэша системного промпта, значения режима.
- Хранилище: один файл в контейнере App Group. Содержимое зашифровано (`CryptoKit`, симметричный ключ в Keychain, `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`, не синхронизируется).
- TTL 24 часа. LRU, потолок 200 записей и 2 МБ, что меньше.
- **Изображения не кэшируются никогда** — объём и чувствительность.
- Кэш полностью очищается при смене любого слота, модели или системного промпта.
- В настройках: переключатель с текстом «Переводы сохраняются на устройстве в зашифрованном виде на сутки, чтобы повторный перевод того же текста был мгновенным», кнопка «Очистить кэш» и текущий размер.
- Упоминание в онбординге в блоке про приватность.

### 11.5 Счётчик расхода (F15)

Локальный, без лимитов и блокировок. В настройках показывать за текущий календарный месяц:

- число запросов, раздельно: текст / изображение, `working` / `strong`;
- суммарные входные и выходные токены из полей `usage` ответов провайдера.

Если провайдер не отдаёт `usage` — показывать прочерк для этой строки. **Не оценивать токены самостоятельно**: приблизительная цифра, выданная за факт, хуже её отсутствия.

Кнопка «Сбросить счётчик». Данные — в App Group, никуда не отправляются.

## 12. Обработка ошибок

Никаких сырых сообщений от API в UI. Маппинг:

| Условие | Текст пользователю | Действие |
|---------|--------------------|----------|
| Ключ не задан | «Не задан API-ключ» | Кнопка в настройки |
| HTTP 401 / 403 | «Ключ отклонён провайдером» | Кнопка в настройки |
| HTTP 429 | «Лимит запросов. Попробуйте через минуту» | «Повторить» |
| HTTP 402 / insufficient_quota | «Закончился баланс у провайдера» | Кнопка в настройки |
| HTTP 404 на модели | «Модель недоступна для этого ключа» | Кнопка в настройки |
| Модель не мультимодальна | «Выбранная модель не понимает изображения» | Кнопка в настройки |
| Сильная модель не настроена | кнопка «Точнее» скрыта | — |
| Нет доступа к «Фото» | «Нет доступа к медиатеке» | Кнопка в системные настройки |
| Скриншотов не найдено | «Не нашёл ни одного снимка экрана» | Закрыть |

| Таймаут / нет сети | «Нет ответа от провайдера» | «Повторить» |
| Пустой ответ модели | «Модель вернула пустой ответ» | «Повторить» |
| Прочее | «Ошибка перевода» + код | «Повторить» |

Полный текст ошибки провайдера — в раскрывающейся секции «Подробности», для отладки.

## 13. Хост-приложение

Пять экранов, минимальных:

1. **Онбординг** — что делает приложение и как назначить его стандартным переводчиком. Обязательно: попытка открыть `Настройки → Программы → Стандартные программы → Перевод` по deep link. **Проверить фактическую доступность такой ссылки; если её нет — скриншот-инструкция, не изобретать несуществующую URL-схему.** Отдельными блоками — как добавить кнопку в Пункт управления и назначить её на кнопку «Действие»; блок про приватность, включая кэш.
2. **Модели** — два слота, `working` и `strong`. Для каждого: провайдер, base URL, ключ (secure entry), модель (список из `listModels()` с возможностью ввести вручную), флаг мультимодальности, кнопка «Проверить» → тестовый перевод `Hello, world`.
3. **Языки и промпты** — `primaryTarget`, `secondaryTarget`, `notesMode`, переключатель словарного режима и его пороги, редакторы промптов (текст / изображение / надстройки), редактор глоссария.
4. **Результат перевода** — экран, на который приходят E1/E2/E3.
5. **Отладка и расход** — счётчик (11.5), переключатель и очистка кэша (11.4), таймауты, `maxOutputTokens`, переключатель локального OCR, лог последних 20 запросов **без ключей, без исходных текстов и без изображений** (только: слот, провайдер, модель, тип ввода, режим, размер, латентность, статус, usage).

## 14. Нефункциональные требования

### Производительность

- Время до первого символа перевода текста: цель ≤ 1.2 с на рабочей модели. Это главная метрика продукта.
- Для изображения: ≤ 3 с до первого символа. Пока идёт запрос — показывать миниатюру и индикатор, а не пустой экран.
- Попадание в кэш (когда включён): результат отображается синхронно, без индикатора загрузки.
- Расширения не выполняют ничего тяжёлого при запуске: ни прогрева сети, ни чтения больших файлов, ни миграций. Дешифровка кэша — лениво, только при обращении.

### Ресурсы расширений

App-расширения на iOS работают с жёстким лимитом памяти, значительно меньшим, чем у приложения. Точный бюджет для `TranslationUIProvider` Apple не документирует; для Share Extension он также ограничен, а обработка изображения — самая ресурсоёмкая операция в проекте.

**Действие агента:** измерить фактический бюджет экспериментально для обоих расширений (наращивать аллокацию до `jetsam`-килла, зафиксировать порог) и записать в `NOTES.md`. Проектировать с запасом: даунскейл до кодирования в base64, не держать одновременно оригинал, уменьшенную копию и base64-строку, стрим обрабатывать инкрементально.

### Приватность

- Исходные тексты и изображения не сохраняются нигде: ни в файлы, ни в `UserDefaults`, ни в логи, ни во временные директории. **Единственное исключение — кэш переводов (11.4), выключенный по умолчанию, зашифрованный, с суточным TTL, только для текста.**
- Единственный сетевой адресат — endpoint, заданный пользователем. Никаких других исходящих соединений. Никакой аналитики.
- Доступ к «Фото» запрашивается только в момент первого использования E2/E3.
- App Privacy в App Store Connect заполнить честно: «Data Not Collected» со стороны разработчика, с пояснением, что текст и изображения отправляются провайдеру, выбранному пользователем.
- В онбординге прямым текстом: «выделенный текст и изображения отправляются на выбранный вами endpoint».

## 15. Тесты

Обязательный минимум, юнит-тесты в `LLMTranslateKit`:

1. **Санитизация ответа** (п. 8.8) — кавычки, префиксы, код-блоки, вложенные кавычки в исходнике (не трогать), пустой ответ. Отдельно: санитизация не применяется к блоку комментариев.
2. **Разбор маркера ⟦NOTES⟧** (п. 8.7) — маркер целиком в одном чанке; маркер, разорванный между двумя чанками в каждой возможной позиции; маркера нет вовсе; маркер есть, блок пуст; текст, начинающийся с символа `⟦`.
3. **Парсинг SSE** для каждого из трёх адаптеров: нормальный поток, разорванный на границе чанка JSON, ошибка в середине, преждевременный обрыв, извлечение `usage`.
4. **Выбор языковой пары** (раздел 7) — все шесть ветвей.
5. **Выбор режима** (11.3) — граничные значения порогов словарного режима: 4 слова, 5 слов, 30 символов, 31 символ, взаимодействие с `notesMode`.
6. **Ключ кэша** (11.4) — одинаковый вход даёт одинаковый ключ; смена любого из компонентов даёт другой; TTL; вытеснение по LRU; изображения в кэш не попадают.
7. **Маппинг ошибок** (раздел 12).
8. **Keychain** — запись, чтение из «второго процесса» (эмулировать отдельной access group в тестовом таргете), удаление, независимость слотов.
9. **Подготовка изображения** (п. 10.7) — даунскейл, разные пороги для скриншота и фото, ступенчатое понижение при превышении лимита, отказ на неподъёмном.
10. **Сборка тела запроса** для всех трёх провайдеров, для текста и изображения, для всех трёх режимов — сверка со снапшотами JSON.

Интеграционные тесты с реальными API не автоматизировать — ручной чек-лист.

## 16. Критерии приёмки

Работа выполнена, когда все пункты подтверждены запуском на **устройстве** с iOS 18.4+:

**Текст**

- [ ] Приложение появляется в `Настройки → Программы → Стандартные программы → Перевод` и выбирается там.
- [ ] Выделение текста в Safari → «Перевести» → открывается **наша** шторка, не Apple Translate.
- [ ] Перевод стартует сам, без нажатия кнопки, и идёт потоком.
- [ ] В редактируемом поле (Заметки) кнопка «Заменить» есть и реально подменяет текст.
- [ ] В нередактируемом контексте (Safari) кнопки «Заменить» нет, приложение не падает.
- [ ] Иврит → русский и английский → русский переводятся корректно; определённый язык отображается верно.
- [ ] Выделение русского текста переводит его в `secondaryTarget`, а не «в самого себя».

**Качество, комментарии, стоимость**

- [ ] Настроены два слота у **разных** провайдеров; оба работают.
- [ ] «Точнее» переспрашивает сильную модель и заменяет результат; подпись показывает, какой моделью сделан текущий перевод.
- [ ] При ненастроенном `strong` кнопки «Точнее» нет.
- [ ] «Пояснить» возвращает комментарии; они попадают в свёрнутую секцию, а не в текст перевода.
- [ ] Секция «Пояснения» не разворачивается сама.
- [ ] Выделение одного слова даёт словарную выдачу с раскрытыми вариантами; выделение абзаца — чистый перевод.
- [ ] Модель, не поставившая маркер, не ломает вывод: весь ответ показан как перевод.
- [ ] Кэш выключен по умолчанию. После включения повторный перевод того же текста отображается мгновенно, без индикатора.
- [ ] Смена модели или промпта очищает кэш.
- [ ] Изображения в кэш не попадают. Проверено осмотром файла кэша.
- [ ] Счётчик показывает ненулевые токены там, где провайдер отдаёт `usage`, и прочерк там, где не отдаёт.

**Скриншоты и автоматизация**

- [ ] Скриншот → тап по превью → «Поделиться» → наше приложение → перевод.
- [ ] Обе команды видны в приложении «Команды» **сразу после установки**, без ручного добавления.
- [ ] Голосовой вызов по фразе срабатывает.
- [ ] Кнопка есть в Пункте управления и назначается на кнопку «Действие»; нажатие переводит последний скриншот.
- [ ] `TranslateImageIntent` принимает изображение из пользовательской команды, собранной вручную.
- [ ] Отказ в доступе к «Фото» даёт понятную ошибку, а не краш и не пустой экран.
- [ ] Скриншот даунскейлится до 1024 px, фотография — до 1568 px.

**Общее**

- [ ] Работают все три провайдера, каждый — с дефолтным и с кастомным base URL, для текста и для изображения.
- [ ] Ключи обоих слотов читаются всеми расширениями без перезапуска устройства.
- [ ] Все сценарии ошибок раздела 12 воспроизведены вручную и показывают правильный текст.
- [ ] Ключ отсутствует в логах, в `UserDefaults`, в файлах контейнера. Проверено грепом по контейнеру.
- [ ] Исходные тексты и изображения не остаются на диске при выключенном кэше. Проверено осмотром контейнера.
- [ ] Юнит-тесты раздела 15 проходят.

**Записано в `NOTES.md`**

- [ ] Фактическая сигнатура метода завершения (п. 4.5).
- [ ] Фактические лимиты памяти обоих расширений (раздел 14).
- [ ] Фактический список языков `supportedRecognitionLanguages()` на тестовом устройстве, с явным ответом про иврит (п. 10.6).
- [ ] Фактический лимит числа App Shortcuts (п. 10.9 предыдущей редакции — см. раздел 10.4).
- [ ] Существует ли рабочий deep link в раздел стандартных программ (раздел 13, п. 1).
- [ ] Замеренное время до первого символа на рабочей и на сильной модели.

## 17. Этапы

| Этап | Содержание | Выход |
|------|------------|-------|
| **0. Разведка** | Создать проект, добавить entitlement и extension-таргет, вывести в шторке `inputText` задом наперёд. Выяснить реальную сигнатуру `finish`, лимиты памяти, список языков OCR, лимит App Shortcuts, наличие deep link. | Шторка открывается по системному «Перевести». `NOTES.md` со всеми фактами. |

| **6. Кэш и счётчик** | Шифрованный кэш, TTL, LRU, инвалидация; счётчик расхода. | F14, F15. |
| **7. Продукт** | Промпт-редакторы, глоссарий, обработка ошибок, онбординг, RTL, Dynamic Type, локализация. | Кандидат на релиз. |

Этапы 6 и 7 переставимы местами. Кэш — единственная функция в ТЗ, ценность которой не доказана: если на этапе 7 окажется, что латентность и так приемлема, кэш можно выкинуть целиком вместе с его компромиссом по приватности. Это решение принимается по замеру из раздела 16, а не заранее.
