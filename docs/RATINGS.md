# Рейтинг моделей «лучше»: как устроен и как пересматривать

Два рейтинга подсказывают порядок моделей в списках (мастер, экран слота), умолчания для нового
подключения и отключение размышления там, где оно нужно:

- **взвешенный** (качество, цена, скорость) — для **рабочей** модели: быстро и недорого;
- **с упором на качество перевода** — для **сильной** модели («Точнее»), где цена и скорость
  важны меньше. Он **поставляется внутри приложения**
и обновляется только с релизом: удалённого конфига нет (раздел 14 ТЗ — единственный сетевой
адресат это endpoint пользователя).

## Что считают рейтинги

**Взвешенный** = `0,5·качество + 0,3·цена + 0,2·скорость`, 0–100 (веса и константы — в начале
раздела «Рейтинг» файла `bench/bench.py`):

- **качество**: 1, если модель не значимо хуже лидера по chrF++ (парный bootstrap-тест), иначе
  `1 − отставание / 10`; усредняется по парам языков;
- **цена**: $ за 1000 предложений по ценам OpenRouter; 0,03 и ниже → 1, 3,0 и выше → 0 (логарифм);
- **скорость**: медианная задержка полного ответа; 0,5 с и меньше → 1, 10 с и больше → 0 (логарифм).

**С упором на качество** = `0,8·качество + 0,1·цена + 0,1·скорость`, но качество здесь по сырому
отставанию от лидера без порога значимости: `1 − отставание / 6` chrF. Разница в 1–2 пункта
лежит в пределах шума, поэтому этот рейтинг — подсказка, а не вердикт (см. B7).

Модель, у которой удалось меньше 80% запросов, не оценивается. Число предложений (`sentences`)
хранится в каждой записи: при n < 50 цифре верить меньше, и **такие модели в умолчания мастера
не попадают** (`ModelRatings.minSentencesForDefaults`), хотя в списках с баллом остаются.

## Умолчания мастера

- рабочая — лучшая по взвешенному рейтингу;
- сильная — лучшая по качеству среди остальных, **но только если она по качеству не слабее
  рабочей**: «Точнее» на модели, которая по замеру хуже, бессмысленно. Если лидер по качеству —
  сама рабочая модель, сильная остаётся пустой, пользователь выбирает её сам;
- модели, про которые известно, что они не читают изображения, не подставляются (рабочий слот
  получает и скриншоты).

**Это стартовый замер, а не нормальный бенчмарк**: новостной корпус, одна метрика, 100 предложений.
Ограничения и план — `docs/BACKLOG.md`, B7. Результаты и оговорки — `bench/RESULTS.md`.

## Файлы

| Файл | Роль |
|---|---|
| `bench/bench.py` | замер (`run`, `retry`), сводка (`report`), экспорт (`export-measurements`), рейтинг (`rank`) |
| `bench/measurements.json` | **в git**: сводка замеров, из неё пересобирается рейтинг без сырых ответов и корпусов |
| `LLMTranslateKit/Sources/Models/ModelRatingsData.swift` | **генерируется** `rank --swift`, не править руками |
| `LLMTranslateKit/Sources/Models/ModelRatings.swift` | ключи моделей, сортировка, умолчания, свежесть |

Сырые ответы моделей (`bench/results/`) и корпуса (`bench/data/`) в git не кладутся.

## Когда пересматривать

- раз в квартал; приложение само подсвечивает устаревший рейтинг оранжевым в списке моделей
  через 120 дней после замера (`ModelRatings.staleAfterDays`);
- когда вышло новое семейство моделей или сильно изменились цены;
- когда замечено, что умолчание мастера выбирает явно неудачную модель.

## Как пересмотреть

1. Ключ OpenRouter с лимитом на расход (отдельный, удалить после). Ориентир: стартовый замер
   (8 моделей × 2 пары × 100 предложений) стоил около 1,2 доллара.
2. Обновить список кандидатов: `python3 bench/bench.py list-models --grep <компания>`; поправить
   `bench/models-*.txt` (убрать устаревшие, добавить новые).
3. Прогнать (ключ ввести скрытым вводом: `read -s OPENROUTER_API_KEY && export OPENROUTER_API_KEY`):
   ```bash
   cd bench
   python3 bench.py run --models models-main.txt --pair he-ru --n 100 --out results/main-he-ru.jsonl
   python3 bench.py run --models models-main.txt --pair en-ru --n 100 --out results/main-en-ru.jsonl
   python3 bench.py retry --results results/main-he-ru.jsonl results/main-en-ru.jsonl   # упавшие по 429
   ```
   Модели с размышлением (Qwen и подобные) — отдельно, с `--no-reasoning`, и указать их в
   `--reasoning-off` на шаге 5.
4. Посмотреть таблицу: `python3 bench.py report --results results/*.jsonl`. Проверить, что у моделей
   удалось ≥ 80% запросов; иначе `retry`.
5. Экспорт и рейтинг:
   ```bash
   python3 bench.py export-measurements --results <файлы> --reasoning-off <модели>
   python3 bench.py rank --swift ../LLMTranslateKit/Sources/Models/ModelRatingsData.swift
   ```
6. Тесты: `python3 -m unittest -q` в `bench/` и тесты Kit (проверяют, что данные согласованы).
7. Закоммитить `bench/measurements.json`, `ModelRatingsData.swift`, `bench/RESULTS.md`; выпустить сборку.

## Что проверить при пересмотре

- Совпадают ли ключи: модель, которой нет в списке провайдера под тем же ключом
  (`ModelRatings.key(for:)`), останется без рейтинга. Для прямых провайдеров (Anthropic, Gemini,
  OpenAI) идентификаторы отличаются от OpenRouter, нормализация покрывает даты и точки, но не
  переименования.
- Рейтинг мерили через OpenRouter: у прямого провайдера цена и задержка немного другие.
- Не превратился ли «лидер» в модель, которая в приложении ведёт себя иначе (размышление,
  пустые ответы при лимите 2048 токенов).
